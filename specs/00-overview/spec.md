# 助小商系统 — 总览

> 本文件是索引与全局约定，不含功能测试项。功能规则分散在 01~05 各自的 spec.md。

---

## 一句话目标

> 商户发布营销创作任务，客户借助 AI 生成推广内容并自行发布到社交平台，平台回收社媒数据、按商户预设规则自动发放奖励，形成"商户—客户—内容—数据—奖励"闭环。

---

## 角色

| 角色 | 说明 | 关键权限 |
|---|---|---|
| `merchant` 商户 | 发任务、配奖励、审作品、管积分商城 | 只能操作自己的数据 |
| `customer` 客户 | 领任务、生成内容、提交作品、兑奖励 | 只能操作自己的数据 |
| `admin` 管理员 | 平台运营 | 全量读写、封禁账号、处理争议 |

一个用户只能有一种角色（本期不做多角色）。

## 全局约定

1. **接口前缀** `/api`，版本 `/api/v1`（本期只在路径写 `/api`，版本走 Header `X-Api-Version`，默认 v1）。
2. **时间** 全部 UTC 存储，接口传 ISO 8601，前端本地化展示。**72 小时倒计时用 UTC 比较**。
3. **金额** 以「分」为单位的整数存储，禁止浮点。积分是整数。
4. **分页** 统一 `?page=1&size=20`，返回 `{items, total, page, size}`，`size` 上限 100。
5. **错误体** 统一 `{code: "AUTH_CODE_EXPIRED", message: "验证码已过期", detail: {...}}`。
6. **鉴权头** `Authorization: Bearer <access_token>`。access_token 2 小时，refresh_token 30 天。
7. **归属校验** 所有 `/api/me/*` 与 `/api/merchant/*` 端点必须校验资源归属，跨租户一律 403（不是 404）。
8. **幂等** 所有"提交/结算/发放"类写操作必须幂等，重复触发不得重复发钱/发积分。
9. **软删除** 用户可见对象（任务 / job / 作品 / prompt 模板）一律软删（`deleted_at`），**不物理删除**，MinIO 对象保留；`reward_grant` / `point_ledger` / `review_log` / `admin_action_log` 四张审计表**只追加，永不删除与覆盖**。
10. **唯一约束即业务规则** "仅可申诉一次""不重复结算""不重复领取"一律用数据库唯一约束兜底，不依赖应用层判断。
11. **付费方服务端推导** 任何产生 AI 成本的请求，**付款方只能由 `task_id` 及其 `pay_mode` 推导**。请求体出现 `merchant_id` / `payer` / `user_id` 等付费标识一律 `422`。客户端永不指定谁付钱。
12. **密钥不落地明文** 用户自带的 provider API Key 一律 AES-256-GCM 加密存储，**永不出现在任何响应体、日志、异常栈、tracing 中**；只允许白名单 provider，**禁止自定义 `base_url`**（防 SSRF 与密钥外泄）。
13. **前端构建产物由 8002 静态挂载**：8001 的构建产物挂 `/`，8002 后台的挂 `/admin`（两处都是 **HTML 路由**，见下节）。开发期由 Vite dev server + proxy 承担，生产期由 FastAPI 承担。

### 13 展开：静态挂载的行为约定

两个前端都是 **SPA**（客户端路由），所以「文件找不到」不等于「路径不存在」。
挂载必须同时满足下面六条——**它们是这个特性的全部契约**：

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **不带扩展名的路径回落 `index.html`**（`/admin/feedback`、`/merchant` → 200） | 用户刷新深链不能 404。这是 SPA 挂载与普通静态目录的唯一区别 |
| 2 | **带扩展名但文件不存在 → 404，不回落** | 回落会让 `<script src=/admin/assets/gone.js>` 收到一段 HTML，浏览器报语法错。**404 好查得多** |
| 3 | **`/api/*` 永不被静态挂载吞掉** | 未注册的 `/api/*` 必须保持 404。被吞成 `index.html` 会让「端点没实现」伪装成 200 |
| 4 | **挂载只处理 `GET` / `HEAD`**，其余方法 404 | 否则未注册路径的 `POST` 会从 404 变成 405，污染既有错误码契约 |
| 5 | **产物目录不存在 → 一律 404，不得 500** | `StaticFiles(directory=...)` 目录缺失时**导入即抛**，会连累整个后端起不来。挂载必须容忍「还没构建」 |
| 6 | **路径穿越拿不到目录外的文件** | `/admin/../` 之类必须挡住 |

- 产物目录可覆盖：环境变量 `FRONTEND_DIST_DIR` / `ADMIN_DIST_DIR`；默认 `<repo>/frontend/dist`、`<repo>/frontend-admin/dist`。
- 挂载**排在所有 router 之后**注册，不遮挡 `/docs` / `/openapi.json` / `/healthz`。
- **不做**：SSR、预压缩（gzip/br）协商、自定义缓存头、ETag 调优。

## 三条贯穿全局的硬规则

1. **72h 超时自动通过**：商户收到作品审核请求后 72 小时内未处理，系统自动通过并触发奖励结算。
   - 理由：客户不应被商家的拖延卡住。
   - **风险**：等于"不审核就付钱"。必须配合单用户单任务奖励上限（见 05）兜底。

2. **成本熔断优先于用户体验**：AI 生成是花钱的。任一用户/商户超并发或超日预算，一律 429 拒绝，不允许静默降级。
   - 花的钱由**内容所属任务的那个商户**承担（预充值额度制，见 07）：余额不足 → 402，超日限额/并发 → 429。
   - 用户不能指定付费方，也不能拿 A 商户的额度做 B 商户的事。

3. **数据不可篡改可追溯**：所有奖励发放、审核动作、积分变动必须写不可变流水（`point_ledger` / `review_log` / `reward_grant`），且带操作者。禁止 UPDATE 覆盖历史。

## 明确不做（全期范围外）

- ❌ **不发布到任何社交平台**。用户自行下载内容、自行发布。本期不接任何平台发布 API。
- ❌ 不采集曝光量 / 展现量（四个方案都拿不到，已确认放弃）。
- ❌ 不做平台官方 OAuth 授权接入（个人开发者申请不下来）。
- ❌ 不做后端自动爬虫采集（平台明令禁止批量抓取）。
- ❌ 不做自建模型 / 本地 GPU 推理。
- ❌ 不做微信小程序（本期只做 H5，但 API 设计与登录方式预留小程序接入）。
- ❌ 不做真实资金池与提现通道（涉二清合规，本期只记账）。
  - 07 的用户充值 + 报销是**唯一例外（2026-09-15 已确认）**，必须守住：①只走线下对公转账 + 管理员记账，**无在线支付通道**；②报销只退平台额度、**不退现金、不可提现、不可转让**。**这两条任一被打破即构成二清，必须重新评审。**
- ❌ 不做多方分账。
- ❌ 不做 KOL/达人分层运营、不做 MCN 管理。
