# 00-overview · 用例清单

> 本文件只装**全局约定 13「前端构建产物由 8002 静态挂载」**这一件事。
> 00 的其余内容（模块地图 / 技术选型 / 三条硬规则）是索引与约定，
> 不含可测行为，故不在此列。

---

## 为什么这一批值得单独测

「挂个静态目录」看起来是十行代码，**但它的六条契约里有三条是"少写一句就静默坏掉"**：

1. **不带扩展名回落 `index.html`** —— 少了它，深链刷新 404。
   开发期（Vite）永远看不出问题，因为 Vite 自己带回落；**只有生产才暴露**。
2. **`/api/*` 不被吞** —— 少了这句守卫，未注册的 `/api/*` 从 404 变成 200 HTML。
   而 06 的 `FR-01` / `FL-*` 那一批「期望 404」的用例**全都靠 `/api` 的 404**，
   这个守卫一松，它们会**一起变绿在错的地方**。
3. **带扩展名不回落** —— 少了它，前端拿 HTML 当 JS 解析，
   控制台报的是 `Unexpected token '<'`，**而不是**「文件 404」。

所以本批的重点不是「能不能返回 200」，而是**上面三个"什么时候不许 200"**。

## 用例清单（`WS`，12 条）

### A. 两条 spec 边界（2 条）

| ID | 断言 |
|---|---|
| `WS-01` | `GET /admin` → `200`（06 spec 边界原文） |
| `WS-02` | `GET /` → `200`（06 spec 边界原文） |

### B. SPA 回落（3 条）

| ID | 断言 |
|---|---|
| `WS-03` | `GET /admin/feedback` → `200`，且响应体**就是 `index.html` 的内容**（深链刷新不 404） |
| `WS-04` | `GET /merchant`（8001 侧的深链）→ `200`，且响应的就是** 8001 的** `index.html`（两个前端**不串**） |
| `WS-05` | `GET /admin/`（带尾斜杠）→ `200` |

### C. 静态文件本身（2 条）

| ID | 断言 |
|---|---|
| `WS-06` | `GET /admin/assets/app.js` → `200`，`content-type` 含 `javascript`（**不是** `text/html`） |
| `WS-07` | `GET /admin/assets/gone.js` → `404`——**有扩展名一律不回落** |

### D. 不许越界（3 条）

| ID | 断言 |
|---|---|
| `WS-08` | `GET /api/definitely-not-a-route` → `404`，**不是** 200 HTML；且响应体**不含** `index.html` 的内容 |
| `WS-09` | `POST /merchant` → `404`——挂载只处理 GET/HEAD，其余方法不回 HTML（⚠️ 探针不能用 `/api/*`，见下「已知取舍 6」） |
| `WS-10` | 路径穿越：`GET /admin/%2e%2e/secret.txt` → 拿不到产物目录外的文件（`404`，且体里没有那个文件的内容） |

### E. 容忍与不打扰（2 条）

| ID | 断言 |
|---|---|
| `WS-11` | **产物目录不存在** → `/` 与 `/admin` 都是 `404`（**不是 `500`**，也不是 200）；且 `GET /healthz` 仍 `200`（挂载不连累其余路由） |
| `WS-12` | 已有路由不被遮挡：`GET /healthz` → `200`、`GET /openapi.json` → `200` |

## 测试基建

产物用 **`tmp_path` 现造**，不依赖「本机有没有 `npm run build` 过」——
否则这套用例会**因环境而绿**，那是最坏的一种绿。

```python
@pytest.fixture
def dist(tmp_path, monkeypatch):
    """造一份假的构建产物，指给静态挂载。用完恢复，免得漏给别的用例。"""
    (tmp_path / "index.html").write_text("<!doctype html><title>admin-build</title>")
    (tmp_path / "assets").mkdir()
    (tmp_path / "assets" / "app.js").write_text("console.log(1)\n")
    monkeypatch.setattr(web, "ADMIN_DIST", tmp_path)
    monkeypatch.setattr(web, "FRONTEND_DIST", tmp_path)
    return tmp_path
```

> ⚠️ **必须 monkeypatch 模块属性**（`web.ADMIN_DIST`），不能让 `main.py` 里
> 写 `from app.web import ADMIN_DIST` 把它绑成本地名——那样接缝打不中。
> 这条口诀本项目已经踩过三次（见 07 / 04 的根因表）。
>
> 目录**在请求时读**（不是 import 时读），所以不需要重新导入 `app`。

两个前端要能区分，故 fixture 给两份不同的 `index.html`：
`ADMIN_DIST` 里写 `admin-build`、`FRONTEND_DIST` 里写 `frontend-build`，
`WS-04` 靠它断言「`/admin/*` 拿的是后台那份、`/merchant` 拿的是主站那份」。

## 反向验证（2026-09-16 已逐条实测 · 12 条全绿后逐处改坏）

| # | 改坏处 | 实测变红 |
|---|---|---|
| 0 | 整个挂载摘掉（`main.py` 注释掉 `mount_frontends`） | `WS-01` ~ `WS-06` 六条红，**另六条照绿**（见下「第 0 条」） |
| 1 | 去掉「不带扩展名回落 `index.html`」 | `WS-01` / `WS-02` / `WS-03` / `WS-04` / `WS-05`（计划只点了 03 / 04） |
| 2 | 回落条件放宽成「找不到就回落」，不判扩展名 | `WS-07` + **`WS-10`**（计划只点了 07，见下「第 2 条」） |
| 3 | 去掉 `/api/*` 守卫（`reserved=()`） | `WS-08`（**恰好一条**，最干净的一次） |
| 4 | 方法守卫放宽（`_ALLOWED_METHODS` 放开全部方法） | `WS-09`（换过探针后才红，见下「第 4 条」） |
| 5 | `find_asset` 去掉越界判定 | `WS-10` |
| 6 | 目录不存在时直接 `raise`（模拟 `StaticFiles` 不兜底） | `WS-11` |
| 7 | `/` 与 `/admin` 指同一个常量（`default=lambda: ADMIN_DIST`） | `WS-02` / `WS-04` |

每处改完立刻实跑，**确认红在哪几条之后马上改回，再改下一处**——
本项目在 8001 那批踩过「上一处的改动没还原干净，导致下一处假红/假绿」。

### 第 0 条：把挂载摘掉，只有一半用例会红
`WS-07` ~ `WS-12` 那六条（「期望 404」「还活着」）在**没有挂载**时**天然成立**——
404 本来就是「什么都不挂」的默认行为。这是本批最大的假绿陷阱：
**光看这六条绿，完全说明不了挂载是对的**。
所以 3 / 4 / 5 / 6 四条必须各自单独改坏——它们打的不是「有没有挂载」，
而是「挂载在了，那条规则还在不在」。第 3 条只红一条、第 5 条只红一条，
这才证明这两条用例真的钉住了各自那行守卫。

### 第 2 条：`WS-10` 会跟着一起红（计划没预料到）
`WS-10` 的探针文件名是 `secret.txt`——**带扩展名**。把扩展名判定拿掉，
它不再是 404 而是回落到 `index.html` 的 200，于是它跟着 `WS-07` 一起红。
连带关系成立，不算假绿；但它说明 `WS-10` 的绿**同时**依赖「越界判定」与
「带扩展名不回落」两条规则，不是只钉一条。

### 第 4 条：探针选错，`WS-09` 原本测不住（**本轮最该记住的一条**）
计划里 `WS-09` 打的是 `POST /api/definitely-not-a-route`。把方法守卫整个拆掉后，
这条**仍然绿**——因为 `/api/*` 已经被 `_API_PREFIX` 守卫挡掉了，
**方法守卫拆不拆，结果都是 404**。用例声明的因果链（「方法守卫 → 404」）
与实际生效的守卫（前缀守卫）不是同一个东西，于是它对目标改动完全无感。

改成打**不受前缀守卫保护**的路径 `POST /merchant` 后，再拆方法守卫立刻红
（404 → 200 HTML）。**这条是「反向验证不是走过场」的实证**：
不逐处改坏，这条用例会一直绿着，而它守的那行代码删掉也没人知道。

### 设计上的一处偏离计划：没有用两个 `app.mount`
原计划是 `app.mount("/admin", ...)` + `app.mount("/", ...)`。实测发现
**`Mount("/admin")` 编译出的正则是 `^/admin/(?P<path>.*)$`，它不匹配裸的 `/admin`**：
裸 `/admin` 会掉到 `/` 那个挂载上，返回**主站**的 `index.html`——两个前端串了，
`WS-01` 直接红。`Mount` 上没法表达「前缀本身也算命中」，故改为
**只挂一个 `/`，在内部按前缀分派**（`_target()`：`admin` / `admin/...` → 后台产物）。
行为契约六条一字未动，只是实现换了形状；`WS-01` 因此才成立。

## 已知取舍（本批）

1. **不测缓存头与 ETag**。spec 明写「不做」，测了是给未定项上锁。
2. **不测 `HEAD` 的响应体为空**。`HEAD` 由 ASGI 层处理，
   测它等于测 Starlette/uvicorn，不是测我们的规则。规则 4 只主张「只处理 GET/HEAD」，
   故只从「`POST` 不被吞」那一面（`WS-09`）钉。
3. **`WS-10` 用 `%2e%2e` 而不是 `../`**。多数 HTTP 客户端会在发出前把 `../` 规范化掉，
   那样测的是客户端的规范化、不是我们的守卫。用百分号编码才真的把
   「带 `..` 的路径」送到服务端。
   ✅ 实测已证：去掉越界判定后 `WS-10` 返回 **200 且体里就是那个目录外的文件**——
   说明 `%2e%2e` 确实是解码后才到我们手上的，这条探针选对了。
4. **不测真实构建产物**（真跑 `npm run build` 再打一遍）。
   这一条的成本（分钟级、依赖 node）远高于它多覆盖的那点东西——
   真实产物与 tmp 产物在**路由层**没有任何区别。真实产物的正确性由
   `frontend/` 与 `frontend-admin/` 各自的构建（`tsc -b && vite build`）保证。

   > 作为**一次性人工烟测**（不入用例、不依赖本机产物），用 `ASGITransport`
   > 直打真 app + 真 dist 跑过一遍，结论留档：
   > `/` → 681B（主站 index）、`/admin` 与 `/admin/feedback` → 604B
   > （后台 index，脚本引用 `/admin/assets/index-*.js`）、`/healthz` → JSON、
   > `/docs` → Swagger（**未被吞**）、`/api/nope` → 404 JSON、
   > `/admin/assets/index-*.js` → `text/javascript`、`/admin/assets/gone.js` → 404、
   > `/admin/assets/` → 200 index（无扩展名，走回落，符合规则 1）、
   > `/favicon.svg` → `image/svg+xml`、`POST /merchant` → 404、路径穿越 → 404。
   > **这组数字证明「两个前端没串」在真实产物上同样成立**（681 ≠ 604 是真两份文件）。
5. **`WS-12` 断的是「还活着」，不是「没被遮挡」的证明**。
   真正的证明是 `WS-08`：`/api/*` 不被吞。`WS-12` 只是便宜地钉住
   最容易被挂载顺序搞坏的两个路径。
   （第 0 条实测佐证：没有挂载时 `WS-12` 也绿。）
6. **`WS-09` 的探针必须是不受前缀守卫保护的路径**（现取 `POST /merchant`）。
   用 `/api/*` 当探针会被前缀守卫兜住，方法守卫拆掉它照样绿——
   详见「第 4 条」。
7. **不测 `/admin` 与 `/administrator` 的区分边界**。分派只认「等于 `admin`」或
   「`admin/` 开头」，`/administrator` 会落到主站产物。这是有意为之
   （前缀不该被当成路径段的一部分），但没单独用例钉——真串了会体现在 `WS-04`。
